# 2026-10-08 元鸡自动喂养修复

承接聊天“同步物品记忆功能”的最后提交 `9df3473`；本次只修改元鸡自动喂养后端，
保留此前同道商人、制作和容器修复。

## 问题与修复

空饲槽或没有合适引子时，原选择逻辑使用 `FirstOrDefault()`，获得全零的
`ItemKey`。当前游戏的 `ItemKey.IsValid()` 只检查 `Id >= 0`，因此误判为
选到了饲料，阻止继续查询库房、行囊。现在无候选时显式返回 `ItemKey.Invalid`，
继续按饲槽、库房、行囊顺序尝试已开启的来源，并保持低品级优先。

同时修复同一喂养链路的边界：

- 元鸡实例编号从 0 开始，编号 0 也参与喂养；每次通过 `TryGetElement_Chicken`
  核实存在且仍在目标聚落，不把缺失记录返回的默认结构体视为有效元鸡。
- 伏龙剧情参数缺失时继续照料普通元鸡，保守跳过鸡王；剧情正常时仍使用原生
  鸡王离家过滤。
- 原生喂养入口按模板寻找首只元鸡。调用前核对实际目标，遇到同模板歧义时跳过，
  避免误喂其它实例或其它聚落的鸡；调用后确认目标好感度实际增长，再继续喂养。
- 原生入口只消费行囊、饲槽中的物品。库房仍只补扣一次，并按原生消费规则传入
  `deleteItem: true`，清理已消耗的物品实例。
